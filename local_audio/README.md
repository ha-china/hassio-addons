# 本地音频

将运行 Home Assistant 的设备转换为音乐助手播放器。将扬声器、放大器或 USB DAC 插入此盒子，启动此应用程序，它将在音乐助手中与您其他的扬声器一起显示——可以独立播放或与群组同步播放。

该播放器是 [Sendspin](https://sendspin-audio.com)，它是内置于音乐助手的播放和同步协议。

## 您需要什么

- 音乐助手 2.7 或更新版本。Sendspin 已内置于音乐助手中，无法关闭，因此无需启用任何内容。
- 音乐助手和本播放器必须位于同一本地网络上。发现功能和音频通信均保留在局域网内；没有反向代理、HTTPS 或 VPN。
- 一个可以通过有线连接到这台机器的设备来播放声音。

## 开始使用

1. 安装并启动应用程序。
2. 打开 **设置 → 应用程序 → 本地音频 → 音频**，选择您的扬声器连接到的输出。
3. 在音乐助手中，播放器会独立显示，名称为此设备的名称——通常是 **homeassistant**。将 **播放器名称** 设置为一个更好的名称。

无需配置其他内容。音乐助手会通过 mDNS 发现播放器并与其连接。

## 选择声音输出的位置

此应用程序页面中 Home Assistant 的 **音频** 面板用于选择音频卡。这是 Home Assistant 本身的音频路由，所有应用程序共享，这也是选择 USB DAC 的地方。此应用程序自身的配置不会选择输出；音频面板即是全部答案。

在运行应用程序时插入的 USB DAC 需要重启应用程序才会被检测到。

### 此处无法使用直接硬件输出

此应用程序通过 Home Assistant 的音频系统播放，无法直接打开声卡。Home Assistant 不会允许应用程序在未转让机器上其他所有设备的原始访问权限的情况下直接访问音频硬件，这是该应用程序所做的权衡。这就是为什么声卡是在 **音频** 面板中选择的，而不是通过命名 `hw:` 或 `plughw:` 设备选择的。

如果您需要 DAC 独享、逐位级的访问权限，请运行此播放器的容器版本而非应用程序。请参阅
[仓库的 README](https://github.com/music-assistant/local-audio-addon)。

## 连接至特定的服务器

除非发现功能确实不工作，否则请留空 **音乐助手服务器** 字段。设置该字段会使播放器主动跋涉到该地址，而不是等待被发现，同时也**停止其可被发现**。

播放器和服务器仍必须位于同一本地网络音频才能工作。此设置并非用于通过 VPN 或代理访问服务器。

不要在此字段中放入凭据。它在配置页面中以明文显示，并包含在 Home Assistant 备份中。

## 如果声音出现中断

**音频缓冲区**是播放器保持队列的音频量，单位为毫秒。留空则播放器使用其默认值，这对于几乎每个系统都是合适的。如果在繁忙或缓慢的机器上声音卡顿或中断，请调高它，这样队列中就会有更多的音频供间隙播放。代价是曲目开始或跳转时会等待更长时间，因此请逐步调高，而不是直接调至顶部。

## 用音乐开启放大器

**播放开始时运行的命令**和**播放停止时运行的命令**用于需要在演奏期间开启的放大器或灯光。留空两者则不运行任何命令，这几乎是所有系统所期望的。

每个命令均为 shell 命令，并在每个流开始或结束时在此应用程序中按原样执行——因此其效果仅限于此应用程序能达到的范围。`curl`调用智能中继的 HTTP 端点是常见形式：

```
curl -fsS -X POST http://192.168.1.20/relay/0?turn=on
```

命令不会阻止播放，失败的命令会在日志中写入一行而不是停止播放器。它打印的任何内容也会进入日志，这是查看命令未按预期执行时的地方。`SENDSPIN_EVENT`在环境变量中为 `start` 或 `stop`，因此一个命令可以服务这两个字段。

在使用之前有两点值得知道。此处的命令运行权限与此应用程序相同，因此请将此字段视为此机器上的终端——仅粘贴您理解的内容。填入任一字段并不会打开这扇大门：此应用程序有权运行命令，无论您是否设置了它们，因为它在应用程序安装时所需的权限是固定的，而不是在保存设置时。

## 音量、静音和延迟

音量、静音和扬声器延迟会在重启和应用程序更新后在应用程序本身的存储中被保留。

如果此播放器在群组中比其他人稍慢——这可以由放大器或具有其自身处理的主动扬声器造成——请在音乐助手中打开播放器设置，将其延迟（单位为毫秒）调整为音频离开此盒子后该硬件引入的延迟量。播放器随后会将音频提前移交这么多，使其与群组同步而不是滞后。此设置会被记住，因此重启后依然存在。

### 在任何音量下都没有声音

如果播放器出现在音乐助手中并播放，但在任何音量设置下都没有声音输出，故障在于 Home Assistant 的音频输出而不是播放器。最常见的情况是输出已静音或调至零。音乐助手的音量无法提升它：它调整此应用程序发送的音频，而不是发送给它的输出的电平。

该电平是 Home Assistant 的，由此机器上的所有应用程序共享并在重启后被记住，因此可能是其他设置。此应用程序在启动时会在其日志中说明，并命名输出和修复方法。从 Home Assistant 主机控制台或终端应用程序：

```sh
ha audio info
ha audio volume output --index 0 --unmute
ha audio volume output --index 0 --volume 85
```

`ha audio info`列出带有其索引的输出；使用此应用程序通过的输出的索引，即日志中标记的那个。此应用程序不会为您设置电平——它是共享的，因此您可以在**音频**面板中自行选择。

如果`ha audio info`显示的电平已经很高，输出可能被路由到一个插口，该插口没有插入任何设备——例如，卡片上的线路输出，而使用的那根耳机空插即是该卡片的。音频到达了该插口并停止在那里，无论音量如何。请拔下重插扬声器或耳机，这样卡片就能注意到它们并切换，或者从**音频**面板选择已插好的输出。日志在每次启动时都会命名它播放出的端口，因此值得先阅读。

### 如果声音中途停止

一个曾经正常工作但现在消失的输出——Home Assistant 的音频服务重启，或 USB DAC 拔掉——不再让播放器在下一首曲目之前保持静音。它已注意到，并继续尝试重新打开输出：大约一分钟内进行五次尝试，第一次在声音停止后几秒，随后的每次间隔都比上次长。如果输出在这段时间内恢复，音乐会中途继续，而这端则无需做任何事。群组中其他所有内容都会继续不受干扰地播放。

如果在一分钟内没有恢复，播放器会停止提问，并在其日志中说明这一点，而不是无限重试。没有卡住：下一首曲目会重新打开输出，因此一旦丢失的东西再次出现，播放新内容就是恢复的方法。

## 已知的瑕疵

此应用程序是**实验性**的。它起作用，但尚未在真实硬件上经过广泛测试。

- 日志可能包含来自播放器构建所依赖的 mDNS 兼容性层的一次性警告横幅。它在播放器自身的日志格式之外打印，且无害。

问题和建议属于
