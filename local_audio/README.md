# 本地音频

将运行 Home Assistant 的机器转换为音乐助手播放器。将扬声器、放大器或 USB 数模转换器连接到该设备，启动此应用，它便会出现在音乐助手界面中，与其他扬声器并列——可独立播放或与群组同步播放。

该播放器使用的是 [Sendspin](https://sendspin-audio.com)，这是内置于音乐助手的回放与同步协议。

## 所需内容

- Music Assistant 2.7 或更新版本。Sendspin 已集成进 Music Assistant，无法关闭，因此无需启用任何内容。
- Music Assistant 和本播放器位于同一本地网络。发现与音频功能均保留在局域网内；无需反向代理、HTTPS 或 VPN。
- 需要连接到此机器并播放音频的硬件设备。

## 快速开始

1. 安装并启动该应用。
2. 打开 **设置 → 应用 → 本地音频 → 音频**，选择您的扬声器对应的输出设备。
3. 在音乐助手中，播放器会单独出现，名称默认为此机器名称——通常为 **homeassistant**。请将 **播放器名称** 修改为更合适的名称。

无需其他配置。音乐助手将通过 mDNS 发现该播放器并与其连接。

## 选择声音输出位置

此应用页面中的 **音频面板** 用于选择音频输出设备（声卡）。这是 Home Assistant 自身的音频路由系统，所有应用共享此系统，也是选择 USB 数模转换器的地方。本应用的任何配置都不会单独选择输出；音频面板即是全部答案。

当应用运行时插入 USB 数模转换器，直到重启应用才开始被识别。

### 此处不可直接访问硬件输出

此应用通过 Home Assistant 的音频系统播放，无法直接打开声卡。Home Assistant 不会授予应用对音频硬件的原始访问权限，除非它也授予该机器上所有其他设备的访问权限——此应用并未为此做权衡。因此，音频输出是在 **音频面板** 中选择的，而非通过命名 `hw:` 或 `plughw:` 设备来实现。

如果您需要 DAC 独占且逐位无损的访问权限，请运行此播放器的容器版本而非应用版本。请参阅 [仓库 README](https://github.com/music-assistant/local-audio-addon)。

## 连接到特定服务器

除非发现功能确实不起作用，否则请留空 **音乐助手服务器** 字段。设置该字段会使播放器直接向该地址连接，而不是等待被查找，同时也会 **使其不再可被发现**。

播放器和服务器仍需位于同一本地网络，音频功能才能正常进行。此设置并非用于通过 VPN 或代理访问服务器。

请勿在此字段中填写凭据。它在配置页面中以纯文本显示，并会包含在 Home Assistant 备份中。

## 如果声音出现中断

**音频缓冲区** 指播放器预留的音频数据量，单位为毫秒。留空则播放器使用其自身默认值，这对绝大多数系统均已足够。若声音在繁忙或性能较差的机器上出现卡顿或中断，可适当提高该值——此时会预留更多数据以填补空白时期的播放。代价是曲目开始和跳转时会稍长一点等待，因此建议循序渐进地调整，而非直接设置到最大值。

## 随音乐开关放大器

**播放开始时运行的命令** 和 **播放停止时运行的命令** 用于控制应在该播放器工作时保持开启状态的放大器或灯光。两者均留空则无命令执行，这对绝大多数系统都足够理想。

每一项均为 shell 命令，并按原样在此应用内执行——每當有音频流开始或结束时都会执行一次——因此效果取决于此应用能触及的范围。例如连接到智能中继器 HTTP 端点的常用命令如下：

```
curl -fsS -X POST http://192.168.1.20/relay/0?turn=on
```

该命令不会阻止回放；若命令失败，则在日志中写入一行而非停止播放器。任何输出内容也会写入日志，当命令未按预期运行时，应从日志中排查。`SENDSPIN_EVENT` 环境变量中会包含 `start` 或 `stop`，因此一个命令可同时满足两个字段的需求。

在使用前需了解两件事：此处执行的命令拥有与该应用相同的权限，因此应像对待这台机器上的终端一样对待该字段——并且仅粘贴您明确理解的内容。填充任意字段并不意味着会因此打开权限之门：此应用无论是否设置命令都允许执行命令，因为它所需的权限在安装时已固定，而非在保存设置时确定。

## 音量、静音与延迟

音量、静音状态和扬声器延迟会记住跨重启和应用更新状态，存储在应用自身的存储中。

如果该播放器在群组中与其他设备稍有延迟——例如放大器或带有自身处理功能的主动扬声器就会发生这种情况——请在音乐助美中打开播放器的设置，将其延迟（单位为毫秒）调整到略大于音频离开本设备后该硬件产生的延迟。播放器将比预期更早交出音频，从而与群组保持同步而非落后。此设置会被记住，因此重启后依然存在。

### 任何音量下均无声音

如果播放器能在音乐助美中正常显示并播放，但无论音量设置如何均无声音输出，问题出在 Home Assistant 的音频输出而非播放器上。最常见的情况是该输出被静音或调至零。音乐助手无法提升音量：它仅调整此应用发送的音频，而不调整最终输出的电平。

该电平属于 Home Assistant，由机器上所有应用共享，并在重启后保持记忆，因此可能由其他因素更改。此应用在启动时会通过日志说明实际情况，并指出输出设备及解决方案。可通过 Home Assistant 主机控制台或终端应用执行以下命令：

```sh
ha audio info
ha audio volume output --index 0 --unmute
ha audio volume output --index 0 --volume 85
```

`ha audio info` 列出了输出设备及其索引编号；请使用此应用实际使用的设备对应的索引编号（即日志中指定的那一项）。此应用不会为您设置电平——该系统为共享资源，因此您可在 **音频面板** 中自主选择。

如果 `ha audio info` 显示电平已在正常范围，则输出可能已路由至连接着插头的未使用的端口——例如该卡上作为耳机插孔使用的线路输出端。音频已到达该插座并在此终止，无论音量如何。请拔下并重新插入扬声器或耳机，使该卡能识别并切换，或从 **音频面板** 中选择已连接的实际输出。日志中每条启动时会记录正在输出的端口名称，因此值得先查看。

### 声音中途停止

原本是正常工作而后消失的输出——例如 Home Assistant 音频服务重启或拔下 USB 数模转换器——此时播放器不会在下一曲目开始前保持沉默。它会意识到并继续尝试重新打开输出：约在一分钟内进行五次尝试，第一次在声音停止后数秒触发，之后每次间隔逐渐变长。若在此时间内输出恢复，歌曲将在中途继续播放，无需做任何处理。组中其他播放的设备将 unaffected 地持续运行。

若一分钟内无法恢复，播放器便会停止重试并在日志中留言说明情况，而非无限重试。并无阻塞：下一曲目会重新打开输出，因此一旦丢失的设备重新连接，只需播放新曲目即可恢复。

## 已知的局限性

此应用处于 **实验性** 阶段。它已可用，但未经过广泛真实硬件测试。

- 日志可能会显示来自 mDNS 兼容层的一次性警告横幅，该层是播放器所基于的基础设施。此信息打印在播放器自身日志格式之外，且无害。
