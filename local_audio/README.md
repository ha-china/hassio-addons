# 本地音频

将运行 Home Assistant 的设备转变为 Music Assistant 的播放器。将扬声器、放大器或 USB 解码器插入该盒子，启动此应用，它便会出现在 Music Assistant 中，与您其他的扬声器并列——可以独立播放或与群组同步播放。

播放器是 [Sendspin](https://sendspin-audio.com)，它是内置于 Music Assistant 的播放和同步协议。

## 您需要的条件

- 一个支持 Sendspin 的版本为 1.0.0-rc1 或更新的 Music Assistant（基于 aiosendspin 10 或更高版本）。旧版本完全无法连接到此播放器。Sendspin 已内置于 Music Assistant 中且无法关闭，因此无需启用任何设置。
- Music Assistant 和本地播放器位于同一个本地网络上。发现及音频均保留在本地局域网内；无需反向代理、HTTPS 或 VPN。
- 需要一个有线连接到此设备的播放设备。

## 开始使用

1. 安装并启动应用。
2. 打开 **设置 → 应用 → 本地音频 → 音频**，选择扬声器所在的输出设备。
3. 在 Music Assistant 中，该播放器将独立出现，以该设备的名称命名——通常名为 **homeassistant**。请将其 **播放器名称** 改为更合适的名称。
4. 如果 Music Assistant 运行在同一个 Home Assistant 系统上，它将自动与播放器配对。否则请手动配对——见下文。

无需其他配置。Music Assistant 将通过 mDNS 发现该播放器并与其连接。

## 与 Music Assistant 配对

所有与播放器的连接均经过加密，服务器必须先 **配对** 才能播放。尚未配对的服务器可以连接，但会保持空闲状态。配对信息会保存在此应用的数据中，因此能在重启和更新后保留；卸载应用则会清除配对信息。

当 Music Assistant 作为应用运行在同台 Home Assistant 系统上时，无需操作：**本机配对 Music Assistant** 默认已启用，Music Assistant 在连接时即会自动与播放器配对。播放器仅在 Home Assistant 的本地网络（`172.30.32.1`）上提供配对令牌，同一机器上的应用可访问，而网络中的其他设备无法访问，且仅限在已配对前有效。端口为 8929；若日志提示端口已被占用，则请设置 **本地配对端口**。只要此开关开启，令牌不会显示在日志中。

若 Music Assistant 运行在其他机器上，有两种配对方式：

- **配对令牌**。关闭 **本机配对 Music Assistant** 并重新启动应用。在未配对状态下，启动时日志会显示一次令牌，在一条以 `No server is paired yet.` 开头的行中。复制 `SP:0…` 引号内的字符串，并在 Music Assistant 中粘贴令牌以配对播放器。
- **六位数代码**。请 Music Assistant 使用代码配对。播放器会为此次尝试生成一个代码并将其记录为 `*** Pairing code: 123456 ***`；在 Music Assistant 中输入该代码。

**将令牌视为密码。** 任何拥有该令牌的人都可以将服务器与此播放器配对，且令牌不会更改。一旦服务器完成配对，令牌将不再记录。此应用的日志仅对 Home Assistant 管理员可见。

**允许未配对的服务器播放** 此选项相当于关闭配对：此时网络上任意服务器均可在此处播放而无需配对。除非有必要，否则请保持关闭；该选项的作用是将加密形式化为一项正式要求。

上游的 [配对播放器](https://github.com/Sendspin/sendspin-cpp-cli/wiki/Pairing-a-Player) 页面提供了更详细的说明。

### 从 0.2.x 版本升级

播放器的身份现在是在首次启动时生成的密钥，因此升级后 Music Assistant 会将其识别为新的播放器。旧版本存储的音量、群组等信息不会转移：请重新配对新播放器，将其重新添加到群组中，并移除旧版本。

## 选择音频输出设备

此应用页面中的 **音频** 面板在 Home Assistant 中选择音频卡。这是 Home Assistant 自带的音频路由设置，所有应用共享，也是选择 USB 解码器的地方。此应用自身的配置不会选择输出设备；音频面板即为全部答案。

当运行应用期间插入 USB 解码器时，该设备不会立即被识别；需重启应用才能在下一次识别到。

### 此处不提供直接硬件输出

此应用通过 Home Assistant 的音频系统播放，无法直接打开音频卡。Home Assistant 不会授予应用对音频硬件的直接原始访问权限，除非同时授予其对机器上所有其他设备的访问权限，此应用不予交易。因此，音频卡的选取在 **音频** 面板中进行，而非通过命名 `hw:` 或 `plughw:` 设备。

若您需要 DAC 的独占、逐位访问，请运行此播放器的容器版本而非应用。参见
[仓库 README](https://github.com/music-assistant/local-audio-addon)。

## 将输入流传输至 Music Assistant

**音频输入** 将此机器的音频发送至 Music Assistant，适用于连接至线路输入或麦克风的唱机或房间内的麦克风。当已与该播放器配对后，它将出现在 Music Assistant 的 **实时输入** 下，并可由任意播放器或群组播放。您需在 Music Assistant 中实际播放该输入时，才会开始捕获。

- `off` 不传输任何音频，为默认选项。
- `audio_panel` 使用此应用 **音频** 面板中选择的输入。更改后需重启应用。
- `named_source` 捕获 **输入源名称** 中指定的来源或汇流排名称，这是音频面板未提供的选项：为其他应用或蓝牙设备播放至该汇流排的内容进行捕获。
- `test_tone` 传输 440 Hz -tone，用于检查输入是否到达 Music Assistant，在涉及任何硬件之前。

若输入不可用，播放器仍可正常启动并播放。它不提供输入，且日志会说明原因并列出其可识别的来源和汇流排名称，这也是确定可用名称的方法。若名称不存在，则需先连接蓝牙设备再启动应用；首次连接后重启应用。

### 无任何设备插入时，输入可能缺失

许多音频卡在插入线路输入或麦克风设备之前无法提供任何输入，因为卡片启动时处于仅支持输出的配置模式。**输入卡片配置** 在应用启动时切换卡片至包含输入的配置模式。使用 `named_source` 时，输入在此启动时即被捕获。使用 `audio_panel` 时，仅当切换卡片后该输入才会在音频面板中显示，因此请在此选择并重启应用。此后拔插设备则保持切换后的状态。

设置值应为卡名称和配置模式的名称，以冒号分隔：

```text
alsa_card.pci-0000_00_1f.3:output:analog-stereo+input:analog-stereo
```

`ha audio info` 命令会列出两者。设置一个当前不存在的名称，日志会列出可用的配置模式。应用仅切换至可用配置模式，并保持卡片的当前输出状态，因此扬声器会继续播放。

此配置将对该机器上的 **所有应用和附加组件**生效，而不仅限于此应用，且 Home Assistant 会在重启后保持该配置。取消设置可通过清空配置值并在 Home Assistant **音频**面板中勾选卡片的先前配置模型来完成。

Music Assistant 不应获取自身发出的音频，因此此应用拒绝捕获其正在播放的输出。`audio_panel` 若没有真实输入，也拒绝回退至捕获本机播放的内容。

## 连接到特定服务器

除非发现功能确实失效，否则**Music Assistant 服务器**字段留空。设置该字段意味着播放器将直接连接至该地址，而不再等待被自动发现，同时**停止被发现**。

播放器和服务器仍需处于同一本地网络，音频才能正常工作。此设置并非用于通过 VPN 或代理访问远程服务器。

请勿在此字段输入凭据。该字段在配置页面中以明文显示，并包含在 Home Assistant 的备份中。

## 若音频出现中断

**音频缓冲区** 指播放器缓存音频的量，单位为毫秒。保持为空，则播放器使用其默认值，该值对绝大多数系统均已适用。若音频出现卡顿或断流（在繁忙或低速的机器上），可适当增加缓冲区大小，以便在间隙中有更多音频可供播放。代价是曲目开始和跳转时会稍慢，请逐步增加而非直接调至最大值。

## 当出现问题时

**日志级别** 控制播放器在此应用日志中产生的记录量。在排查问题时将其调至 `debug`，问题解决后改回 `info`。

## 通过音乐开启放大器

**播放开始时运行的命令** 和 **播放停止时运行的命令** 用于控制放大器或应在此播放器发声期间开启的灯具。两者留空则不执行任何操作，这几乎符合所有系统的默认需求。

每个值均为 shell 命令，作为普通命令在应用内执行——在每次流开始或结束时执行——因此其效果仅限于应用所能触达的范围。对智能中继器 HTTP 端点的 `curl` 请求是常用格式：

```
curl -fsS -X POST http://192.168.1.20/relay/0?turn=on
```

命令不会暂停播放，若失败则在日志中写入一行而非停止播放器。其输出任何内容会同时写入日志，这是诊断命令未按预期运行时的地方。环境变量中 `SENDSPIN_EVENT` 为 `start` 或 `stop`，因此一条命令可同时服务这两个字段。

使用此功能前需知两点。此处的命令以与此应用相同的权限运行，因此请像对待此机器的终端一样对待该字段——仅粘贴您理解的内容。填充任一字段并不会直接打开权限之门：此应用允许您运行命令，无论是否设置了命令，因为其所需的权限是在安装应用时设定固定的，而非保存设置时。

## 音量、静音和延迟

音量、静音和扬声器延迟会在重启和应用更新后保存于应用自身的存储中。

若该播放器在与群组中的其他成员（如放大器或配备处理电路的主动式扬声器）相比稍有延迟，请在 Music Assistant 中打开播放器的设置，增加其延迟值（单位：毫秒），使其匹配音频离开该盒子后该硬件所引入的延迟。播放器会提前这么多时间传递音频，从而与群组同步，而非滞后。此设置将被保存，因此重启后依然有效。

### 任何音量下均无声

若播放器在 Music Assistant 中可见并可播放，但在任何音量设置下均无声音输出，则故障在于 Home Assistant 的音频输出设置，而非播放器本身。最可能的原因是该输出已被静音或音量调至零。Music Assistant 的音量控制无法改变此设置：它仅调节本应用发送的音频电平，而非其被发送至输出设备的电平。

该电平由 Home Assistant 管理，该机上的所有应用共享，并在重启后保留。此应用在其启动日志中会指出这一情况，并指明输出设备及修复方法。从 Home Assistant 主机控制台或终端应用程序运行：

```sh
ha audio info
ha audio volume output --index 0 --unmute
ha audio volume output --index 0 --volume 85
```

`ha audio info` 会列出输出设备及其索引；请使用此应用所用输出设备的索引，日志中即为该索引。此应用不会代为设置电平——由于该设置由所有应用共享，因此应通过在 **音频**面板中自行选择该电平。

若 `ha audio info` 显示电平已提升，则输出可能被路由至一个未插设备的端口——例如卡片线路输出端口，当前使用的是耳机插口。音频到达了该插口即终止，无论音量大小。拔除并重新插入扬声器或耳机，即可让卡片检测到设备并切换，或在 **音频**面板中选择已插好设备的输出。日志每次启动时都会指出其正在使用的端口，因此建议先查看日志。

### 若在播放中途失去声音

原本可用的输出突然失效——Home Assistant 的音频服务重启或 USB 解码器被拔除——此后该播放器不会在下一曲目前保持静音。它已察觉并持续尝试重新打开输出：连续约五分钟内尝试五次，首次尝试发生在声音停止后几秒，后续每次间隔时间均比前一次更长。若在此时间内输出恢复，音乐会在曲目中途继续，而本端无需操作。群组中的其他播放设备将不受影响地继续播放。

若无输正在恢复的窗口内仍未恢复，播放器将停止尝试，并在日志中说明，而非无限重试。无需担心卡死：下一曲目会重新打开输出，因此一旦缺失的硬件再次出现，即可通过播放新曲目恢复。

## 已知缺陷

此应用处于 **实验性** 阶段。它目前可用，但尚未经过广泛的主流真实硬件测试。

- 日志可能包含由播放器所依据的 mDNS 兼容性层产生的一次性警告横幅。该横幅打印在播放器日志格式之外，无害。
