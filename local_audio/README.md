# 本地音频

将运行 Home Assistant 的设备变为音乐助理播放器。将功放、音箱或 USB 数模转换器（DAC）插入该设备，启动该应用程序，它就会在音乐助理中与其他音箱一同显示——支持独立播放或与群组同步。

该播放器基于 [Sendspin](https://sendspin-audio.com)，这是音乐助理内建的播放和同步协议。

## 所需内容

- 一台支持 Sendspin 1.0.0-rc1 的音乐助理（基于 aiosendspin 10 或更高版本）。旧版本无法以任何方式连接到此播放器。Sendspin 已集成在音乐助理中，无法关闭，因此无需启用它。
- 音乐助理和此播放器位于同一本地网络。发现和音频流均留在局域网内；无需反向代理、HTTPS 或 VPN。
- 某种可通过有线接口连接到此设备的播放输出设备。

## 开始使用

1. 安装并启动该应用程序。
2. 打开 **设置 → 应用程序 → 本地音频 → 音频**，选择您的音箱所在的输出设备。
3. 在音乐助理中播放器会出现，并以该设备的名称命名——通常为 **homeassistant**（即“家庭助手”）。将 **播放器名称** 设置为更好的名称。

4. 如果音乐助理运行在同一台 Home Assistant 系统上，它将自动与播放器配对。否则，请手动配对——见下方。

无需额外配置。音乐助理将通过 mDNS 发现并连接到此播放器。

## 与音乐助理配对

每次连接到播放器都需要加密，服务器必须首先**配对**后才能播放。未配对的服务器可以连接但处于空闲状态。配对记录会保存在该应用程序的数据中，因此在重启和更新后依然有效；卸载应用程序会清除配对记录。

当音乐助理运行在同一台 Home Assistant 系统上的应用程序时，无需任何手动操作：**在本机上与音乐助理配对**默认已开启，音乐助理在连接时会自动与播放器配对。播放器仅在其配对令牌在 Home Assistant 内部网络（`172.30.32.1`）可用时提供该令牌，本机上的应用程序可以访问，而您网络中的其他设备无法访问，且仅在服务器配对后才有效。端口为 8929；如果日志显示端口已被占用，请设置 **本地配对端口**。只要此项启用，令牌就不会出现在日志中。

对于运行在其他机器上的音乐助理，有两种配对方式：

- **配对令牌**。关闭 **在本机上与音乐助理配对** 并重启应用程序。在尚未配对时，启动日志会显示一次令牌，标签以 `No server is paired yet.` 开头，随后行显示 `Pairing token`。复制 `SP:0…` 开头的字符串，并将其粘贴到音乐助理要求输入播放器令牌以进行配对的位置。
- **六位代码**。让音乐助理通过代码进行配对。该播放器会为此次尝试生成一个代码，并记录为 `*** Pairing code: 123456 ***`；将其输入到音乐助理中。

**请将令牌视为密码。** 任何拥有该令牌的人都可以将服务器与此播放器配对，且该令牌不会更改。一旦服务器配对成功，令牌将不再被记录。应用程序日志仅对 Home Assistant 管理员可见。

**允许未配对服务器播放** 将关闭配对功能：此时，您网络中的任何服务器均可在此播放而无需配对。除非另有原因，否则请保持该选项关闭；它的作用是将加密恢复为一种形式。

上游的 [配对播放器](https://github.com/Sendspin/sendspin-cpp-cli/wiki/Pairing-a-Player) 页面提供了更详细的说明。

### 从 0.2.x 版本升级

现在，播放器身份是其启动时生成的一对密钥，因此升级后音乐助理会将此视为新播放器。旧播放器保存的音量、分组等设置不会转移：请配对新播放器，重新将其加入群组，然后删除旧播放器。

## 选择声音输出方式

此应用在 Home Assistant 中页面显示的 **音频** 面板用于选择音频设备。这是 Home Assistant 自身的音频路由系统，供所有应用程序共享，也是选择 USB DAC 的地方。此应用的任何配置选项都不会单独选择输出；音频面板即为完整答案。

当应用程序运行时插入的 USB DAC 直到重启应用程序后才会被识别。

### 此处不提供直接硬件输出

此应用通过 Home Assistant 的音频系统播放，无法直接打开音频设备。Home Assistant 不会授予应用程序对音频硬件的原始访问权限，除非也授予其访问机器上所有其他设备的权限，而本应用不会进行这种权交易。这就是为什么音频设备选择在 **音频** 面板而不是通过命名 `hw:` 或 `plughw:` 设备来匹的原因。

如果您需要 DAC 独占且无损的访问权限，请运行此播放器的容器版本而非应用程序。请参阅
[存储库的说明文件](https://github.com/music-assistant/local-audio-addon)。

## 将输入流传输至音乐助理

**音频输入** 函数将从本机传输音频流至音乐助理，用于将唱机连接到线路输入，或将房间内的麦克风拾音。一旦音乐助理已与此播放器配对，该输入会在音乐助理的 **实时输入** 下显示，并可被任何播放器或群组播放。未实际播放前不会进行捕获。

- `off` 不传输任何内容，为默认设置。
- `audio_panel` 使用本应用 **音频** 面板所选的输入。更改后需重启应用程序。
- `named_source` 捕获 **输入源名称** 中指定的源或汇，供音频面板未提供的使用：命名一个汇可捕获另一个应用程序或蓝牙设备播放至此的内容。
- `test_tone` 传输 440 Hz 的测试音调，以便在涉及任何硬件前检查输入是否成功到达音乐助理。

如果输入不可用，播放器仍会正常运行并播放，只是不提供输入。其日志会说明原因并列出其可识别的源和汇，这也是查找可用名称的方法。这覆盖名称不存在的情况，因此蓝牙设备必须在应用程序启动前连接：一旦连接好，请重启应用程序。

### 当插线为空白时输入缺失

许多声卡在线路输入或麦克风插孔未接入任何设备时不提供任何输入，因为声卡启动时处于仅包含输出的配置文件。**输入卡配置文件** 在应用程序启动时将声卡切换为同时包含输入的配置文件。使用 `named_source` 时，输入在此刻捕获。使用 `audio_panel` 时，只有在应用程序切换此配置文件后，输入才会在音频面板中出现，因此请从中选择并重启应用程序。之后再拔掉线缆会保持该状态。

将其设置为卡名和配置文件名，中间用冒号分隔：

```text
alsa_card.pci-0000_00_1f.3:output:analog-stereo+input:analog-stereo
```

`ha audio info` 命令会列出两者名称。设置一个不存在的名称，日志会列出可用的配置文件。应用程序仅会切换到可用配置文件并保留声卡当前输出，因此扬声器会继续播放声音。

此改动会影响本机上的**所有应用程序和插件**，而不仅限于此应用，Home Assistant 会在重启后保持该改动。要撤销它，请清空该设置并从 Home Assistant 的 **音频** 面板中重新选择卡之前的配置文件。

音乐助理不应获取自身播放的输出，因此此应用拒绝捕获其播放的输出。`audio_panel` 也可能拒绝在无线输入缺失时退而求其次，转而捕获本机播放的内容。

## 连接至特定服务器

除非发现功能确实不起作用，否则请保持 **音乐助理服务器** 字段为空。设置该字段会将播放器发往该地址而非等待发现，且会**同时停止其被发现**。

播放器和服务器仍需位于同一本地网络音频才能工作。此设置并非通过 VPN 或代理访问服务器的手段。

请勿在此字段中输入凭据。该字段在配置页面中以明文显示，并包含在 Home Assistant 备份中。

## 如果声音中断

**音频缓冲区** 指播放器队列中保留的音频时长，以毫秒为单位。留空则播放器使用其默认值，这对几乎所有系统都适用。如果声音在繁忙或运行缓慢的机器上出现卡顿或中断，请增加该值——此时队列中有更多音频可供缓冲，以填补空隙。代价是曲目开始时以及您拖动进度条时会等待更久，因此建议逐步增加而非直接设置为最大值。

## 出现问题时

**日志级别** 设置播放器写入此应用程序日志的内容量。在追踪问题时将其提高了 `debug`（调试）级别，并在问题解决后改回 `info`（信息）级别。

## 随音乐控制放大器开关

**开始播放时运行的命令** 和 **播放停止时运行的命令** 用于在播放器播放期间开启或关闭放大器或应长期开启的灯光。两者留空则表示无操作，这符合大多数系统的预期。

每项均为 shell 命令，且会在每个流启动或结束时严格按照输入在应用程序内运行——因此其效果仅取决于应用程序能触及多远。使用智能继电器 HTTP 端点的 `curl` 命令是最常见的形式：

```
curl -fsS -X POST http://192.168.1.20/relay/0?turn=on
```

命令不会暂停播放，且失败时不会停止播放器，而是在日志中写入一行以说明原因。命令输出的所有内容也会进入日志，此即检查命令未按预期执行时的位置。环境变量 `SENDSPIN_EVENT` 为 `start` 或 `stop`，因此一条命令可同时用于两个字段。

在使用前有两点需要注意：此处的命令拥有与本应用程序相同的权限，因此应按此机器上的终端对待该字段——只粘贴您理解的内容。填写任一字段本身并不意味着开启权限：此应用允许运行命令，无论您是否设置了命令，因为其所需权限是在安装时设定的，而非在您保存设置时设定。

## 音量、静音与延迟

音量、静音和扬声器延迟会记录在应用程序自身的存储中，跨越重启和应用程序更新。

如果此播放器在群组中稍晚于其他设备启动（例如放大器或带有自建处理功能的音箱会出现这种情况），请在音乐助理中打开播放器的设置，将其延迟（以毫秒为单位）调高至音频离开该设备所产生的硬件延迟量。这样，播放器会将音频提前传递，使其与群组同步而非滞后。此设置会在此保留，因此重启后依然存在。

### 任何音量下均无声音

如果播放器在音乐助理中出现并播放，但任何音量设置下均无声音输出，故障出在 Home Assistant 的音频输出而非播放器上。最常见的原因是该输出被静音或调至零。音乐助理的音量无法提升它：它调整的只是此应用程序发送的音频，而非其发送给输出设备的音量电平。

该电平由 Home Assistant 控制，供本机上的所有应用程序共享，且会在重启后保留，因此可能是由其他因素设定。该应用在启动时会在日志中说明此情况，并指明输出设备及修复方法。从 Home Assistant 主机控制台或终端应用程序执行以下命令：

```sh
ha audio info
ha audio volume output --index 0 --unmute
ha audio volume output --index 0 --volume 85
```

`ha audio info` 命令列出带有其索引号的输出设备；使用此应用播放的音频设备索引号（即日志中指定的号码）。此应用不会为您设置电平——因为是共享的，所以您必须在 **音频** 面板中自行选择。

如果 `ha audio info` 显示电平已提升，输出可能被路由到一个接线口未被使用，例如线路输出端口——可能是某张声卡的耳机插口被占用，音频传输到此端口后停止，无论任何音量级别。请拔掉并重新插上扬声器或耳机，声卡会检测到并切换，或者从 **音频** 面板选择一个已连接输出的设备。日志会在每次启动时指明回放输出的端口编号，值得首先阅读。

### 如果播放中途声音停止

原本正常工作随后消失的输出——Home Assistant 音频服务器重新启动或 USB DAC 拔除——不再将此播放器静默直至下一曲目。它已注意到并已继续尝试重新打开该输出：每隔约一分钟提交五次尝试，第一次在声音停止后几秒钟开始，随后每次间隔越来越长。如果在限定时间内输出恢复，音乐将在曲目中途继续播放，而无需在此端做任何操作。群组中播放的其他内容全程不受干扰。

如果超过一分钟仍未恢复，播放器会停止循环请求并在日志中说明，而不是无限重试。没有问题卡死：新曲目会重新打开输出，因此一旦缺失的部分再次恢复，只需播放新内容即可恢复正常。

## 已知的不完善之处

此应用属于**实验性**性质。它确实可用，但尚未在真实硬件上进行广泛测试。

- 日志中可能会出现一次的警告横幅，来自播放器所基于的 mDNS 兼容性层。该横幅打印在播放器专属日志格式之外，且无害。
